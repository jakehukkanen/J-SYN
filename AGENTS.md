# J-SYN Architecture & Coding Standards

## Core Priority
**Maintainability and readability for both humans and AI are top priorities.** Prefer small, single-responsibility modules (~150–500 lines), descriptive helper functions, and shared UI/DSP primitives over deeply nested closures or copy-pasted boilerplate.

---

## Crate & Module Map

- `crates/j-syn-dsp/`: Real-time audio-thread DSP engine (zero heap allocations in `process()`, shared phase-warp + PM/RM evaluation in `sample_with_warp_and_pm`):
  - `lib.rs` / `engine.rs` / `voice.rs` / `oscillator.rs` / `envelope.rs` / `wavetable.rs`: Polyphonic synth engine (`64` voices, `Dirty` vs `Clean` interpolation, voice `auto_sleep`, `f64`-precision `~2.5 Hz` DC blocker, optional `-0.1 dBFS` brickwall safety limiter, `WavetableBank` custom `.wav` `2048`-sample frame slicing + mip-maps), plus full **MPE** (`mpe_enabled`, `mpe_pitch_bend_range` `48 st` default, Master `Ch 1` broadcast vs Member `Ch 2–16` isolated Pitch Bend / Channel Pressure / `CC74` Slide, CLAP/VST3 `PolyPressure`/`PolyTuning`/`PolyBrightness`, and `1.5 ms` per-voice expression smoothing).
  - `adaa.rs`: 2nd-order ADAA `tanh` waveshaper (`TanhAdaa2`, ported from Cure Audio `Scream` / `ADAA` / `Polylogarithm`).
  - `noise.rs`: Per-voice stereo White/Pink/Brown noise generator (`NoiseType`, `NoiseParams`, `NoiseState`).
  - `filter.rs`: Dual per-voice ZDF multimode & multi-filter engine (`LP`, `BP`, `HP` with selectable `FilterSlope` `6/12/24/36/48 dB` via pre-allocated `[StereoZdfSvf; 4]` + 1-pole TPT, Cure-style `Scream`, `Daft`, pre-allocated `Comb` delay line, `HP + Peak`, `HP + Notch`, `LP + Notch`, `LP + Peak`, `evaluate_filter_response_db`).
  - `fx/`: Parallel or Serial (`FxBusTopology::Parallel` `A | B` vs `FxBusTopology::Serial` `A -> B`) dual-bus 8-slot Master FX Rack (`Bus A` & `Bus B` + `Sub Bus` clean Direct Out when bypassed) with per-slot stacking (`STACK 1..4`) and zero audio-thread heap allocations (`mod.rs`: `FxType` including `Dispersion` [`Diopser`] & `Phaser`, `FxBusTopology`, `FxFilterSlope`, `FxSlotParams`, `FxBusParams`, `SubBusParams`, `SubBusProcessor`, `FxRackParams`, `FxRackState`, shared `flush_denormal`/`track_idle`; `dynamics.rs`: `OttStereo`, `DistortionStereo`, `JSatClipperStereo`; `modulation.rs`: `EqStageStereo`, `ChorusStereo`, `PhaserStereo`, `DelayStereo`, `ReverbStereo`; `diopser.rs`: pre-allocated 128-stage cascaded RBJ allpass bank `DiopserStereo` & `evaluate_diopser_ripple`).
  - `oversample.rs`: Zero-allocation 4x polyphase IIR half-band oversampler (`Oversampler4x`) and RBJ LP/HP/AP/Shelf `Biquad` / `BiquadCoeffs` ported from `crushclone-rs`.
  - `insert.rs`: Dual per-voice insert waveshapers (`Tube`, `Mech`, `Tube -> Mech`, `Mech -> Tube`, `SineShaper`, `Parabolic`, `SoftClip`, `Bitcrush`) + `Serial`/`Parallel` filter routing, `DirectDest` (`Off`/`BusA`/`BusB`/`Sub`), `FilterBusDest` (`BusA`/`BusB`/`Both`/`Sub` — where `Both` routes to `Bus A` only in `Serial` mode to prevent double-feeding `Bus B`), and feedback bus state (`InsertParams`, `RoutingParams`, `InsertShaperState`, `VoiceFeedbackState`).
  - `mod_matrix.rs`: Lock-free 32-slot modulation matrix (`ModMatrixSource` with 21 active sources including per-voice `Aftertouch` & `Slide` `CC74`, `ModDestination` with 198 destinations covering `Bus A` & `Bus B` `FX1..8 P1..8` + `Sub Bus` + `Bus Level/Pan`, `ModSlot` with `enabled`, `bypassed`, `aux_source`, `curve`, `ModMatrixState`, `FxScopeRing`, `ModUiTelemetry`).
  - `modseq.rs`: 4 hybrid 16-step `MODSEQ` / breakpoint `LFO` curve modulators (`ModSeqMode`, `ModSeqStepShape` with 18-tile `PALETTE` including 2x/3x subdivisions, `ModSeqStep`, `MsegNode`, `MsegCurve`, 9 `LfoPreset` presets including `Sine`, `ModSeqStepBank`, `ModSeqShapePreset`, `ModSeqSyncMode`, `ModSeqRate`, `ModSeqPlayMode`, `ModSeqRetrig`, `ModSeqParams`, `ModSeqState`, `evaluate_step_shape`, `evaluate_modseq_curve`, `evaluate_mseg_curve`).
- `crates/j-syn/src/lib.rs` & `crates/j-syn/src/params/`: `nih-plug` VST3/CLAP plugin wrapper (`lib.rs`) + split parameter definitions (`params/mod.rs` `PersistedArcSwap`/`JSynPluginParams`, `params/osc.rs`, `params/fx.rs`, `params/mod_params.rs`).
- `crates/j-syn/src/presets.rs`: Local `JSynConfig` persistence (`presets_dir`, `wavetables_dir`, `theme`, `ui_scale`), recursive folder scanning (`DirectoryTree`, `DirectoryFolder`, `scan_preset_tree`, `scan_wavetable_tree`), patch JSON save/load, and custom `.wav` wavetable loading.
- `crates/j-syn/src/theme.css`: Base Vizia stylesheet defining layout, spacing, disabled-module dimming, inline readouts, and dropdown/overlay styling (mapped dynamically by `editor/theme.rs`).
- `crates/j-syn/src/editor/`: Modular Vizia GUI:

  - `osc_panel.rs`: Oscillator strip (`OSC 1` – `OSC 4`) builder with custom `.wav` filename label, stretched `WavetableScope`, `WARP` (`None`, `B-`, `B+`, `SP`) + `ArrowButton::reactive` routing order toggle + scrollable unified `MOD` (`Off`, `PM 1..4`, `RM 1..4`) row (`build_osc_panel`).

## GUI & Stability Conventions

- Always use `controls::bold_label(cx, text, class)` instead of repeating `.font_family(...).font_weight(...)`.
- **Self-Contained Vector Icon Buttons & Balanced Centering:** Never put Unicode arrows (`▲`, `▼`, `◀`, `▶`, `<`, `>`, `▾`) or child icon views inside `vizia::Button` (`default_layout.css` imposes `button > .inner { min-left: 8px; min-right: 8px; }`, pushing narrow buttons off-center, and `Button`'s `child-space: 1s` shrinks `Stretch(1.0)` children to 1/3). Always use `ArrowButton`, `CrossButton`, or `VectorArrow::caret` in `controls.rs`, which draw both box and glyph in one `cx.bounds()` pass using balanced rectangular centering (`cx_pt = (b.x + b.w * 0.5).round()`, `cy_pt = (b.y + b.h * 0.5).round()`, `size = b.w.min(b.h) * 0.34` or `4.5 * scale` for carets, `half_span = size * 0.52`, `half_base = size * 0.56`, `nudge = size * 0.04`).
- **Clickable `ZStack` Scope Overlays:** Never place `.hoverable(false)` on a container wrapping interactive overlay buttons/dropdowns (`vizia_core`'s `hover_entity` immediately skips all descendants when `!hoverable`). Apply `.hoverable(false)` only on the underlying canvas view (`FxSlotVisualizer`) and layout spacers, declare the overlay *after* the canvas with `.position_type(PositionType::SelfDirected).z_index(10)`, and use `#rrggbbaa` ghost-translucent idle styling (`:hover` / `:checked` for focus).
- Always use `controls::build_dropdown_trigger_labels` / `build_enum_dropdown` / `build_prefixed_enum_dropdown` / `build_bool_dropdown` / `ScrollDropdown` for dropdowns, and `controls::build_param_readout_box` for numeric readouts; wrap long/nested dropdown menus in bounded `ScrollView` + `build_directory_tree_items`.
- Route **all** `femtovg` colors through `theme::current_palette(cx)` (and CSS hex tokens—both `#rrggbb` and `#rrggbbaa`—through `ThemePalette::map_hex_token`), keeping zero hardcoded unmapped colors in `draw()` or `theme.css`.
- **Single 60 Hz Vizia Timer:** Never add additional `cx.add_timer` loops; extend the single timer in `mod_bar.rs` instead.
- **Split Structural vs. Value Lenses:** Emit `UiEvent::ModValChanged` (`mod_val_rev`) during continuous drags inside `Binding::new(..., UiData::mod_ui_rev, ...)` views so captured drag widgets (`cx.capture()`) are never destroyed mid-drag.
- **CSS & Verification Gate:** Avoid unsupported Vizia CSS selectors (e.g. `:focus-within`, which crashes Ableton Live); run `cargo test --offline --workspace` (verifying CSS parsing, unique `#[id]` strings, single timer, patch/dir/theme tests, MPE & DSP tests) plus `cargo xtask bundle j-syn --release` with zero project compiler warnings before committing.

## Git Workflow & Pull Requests

- **Branch per Issue / Feature:** Always create a dedicated branch off `main` (e.g. `fix/<short-slug>` or `feat/<short-slug>`) when working on an issue or task rather than committing directly to `main`. If tackling multiple unrelated issues, use separate branches off `main` for each.
- **Verify Before Pushing:** Run `cargo test --offline --workspace` and `cargo xtask bundle j-syn --release --offline` (zero project compiler warnings) before opening or merging a PR.
- **Pull Requests:** Once verified on a feature branch, always commit, push the branch to `origin`, and open a Pull Request targeting `main` (`gh pr create`), referencing the issue (`Closes #<n>` when applicable), without waiting for a separate prompt. Only pushing or merging directly to `main` (`git push origin main` or `gh pr merge --merge --delete-branch`) requires explicit user permission; after merging, fast-forward local `main`.
